# Инструкция для ИИ, работающего с проектом через GitHub

Ты продолжаешь работу над мобильной выживалкой на Godot 4.3 (папка `godot/`). Своей консоли у тебя нет: код правишь и пушишь через коннектор GitHub, а Godot и Blender запускаешь на сервере GitHub workflow-ом **Tools**. Потом к проекту вернётся другой ИИ (Claude Code), поэтому всё, что сделал, записывай (см. «Обязательно в конце»).

## Сначала прочитай
1. `CLAUDE.md` — карта проекта, правила владельца, текущее состояние сборок, что где лежит, что уже решено.
2. `docs/ПЛАН.md` — план работ, отмечено, что сделано.
3. `docs/ДИЗАЙН.md` — договорённости с владельцем, таблица масштабов (человек 1,8 м, дверь 2 м и т. д.).
4. `CHANGES_DRAFT.md` — последние изменения.

## Правила владельца (коротко)
- Отвечать коротко, по-русски.
- Сначала замерить причину (лог, числа, снимок), потом чинить. Одна проблема за раз. Не гадать.
- «Пока обсуждаем / ничего не делай» — ничего не менять и не запускать.
- Модели — реалистичные, не мультяшные и не «Лего». Эталон — берёза `tools/trees/birch.py`.
- Инструменты — только Blender (bpy) и Godot.
- Версию в `godot/scripts/hud.gd` вручную НЕ менять (CI подставляет сам).
- Старую браузерную игру (`index.html`, `src/`, `sw.js`) не трогать.

## Как работать
1. Правишь файлы и пушишь в `main` (или в свою ветку для проб).
2. Проверяешь через workflow **Tools**: Actions → Tools → Run workflow (через коннектор — запуск workflow `tools.yml`, событие workflow_dispatch) с полями:
   - `task` — задача;
   - `args` — аргументы (буквы, цифры, `_ , . : @ / -` и пробел).
   Запуск берёт код из выбранной ветки.
3. Результат читаешь в ветке **`tools-out`**: `README.md` (какой запуск), `out/log.txt` (лог), картинки и файлы в `out/`. Ветка перезаписывается каждым запуском. То же лежит во вложении запуска «tools-out» (7 дней).
4. Push в `main` с изменениями в `godot/` сам собирает APK (workflow «Build Godot APK», 10–20 мин) и выкладывает его:
   https://github.com/emrysmxo-maker/survival-game/releases/download/godot-latest/survival-godot.apk
   Эту ссылку давать владельцу после каждой правки.

## Задачи Tools
| task | args | что делает |
|---|---|---|
| `parsecheck` | — | все скрипты и шейдеры разбираются (делать после каждой правки кода) |
| `shot` | `x:y[:cam[:yaw[:elev[:time]]]]/x:y…` [кадров] | снимки игры в точках карты → `out/shots/shot_<точка>_<кадр>.png`. x,y — тайлы (как «Координаты» в игре), cam — приближение в метрах (2–60, обычно 18), yaw — поворот, elev — наклон 22–82, time — часы 0–24. Пример: `-43:-97:30/166:-133:12:45:60:22` |
| `blender` | `путь/скрипт.py` [аргументы] | любой свой скрипт Blender (`import bpy`). Файлы класть в `$OUT` (переменная окружения) — они попадут в `tools-out` |
| `godot` | `godot/scripts/x.gd` [аргументы] | любой свой скрипт Godot (`extends SceneTree`, headless). Для замеров по миру: `WorldGen.init()`, см. `scripts/mapcheck.gd`, `treecheck.gd` |
| `props` | [имена] | пересобрать все постройки, машины и места в `props.glb` + импорт в Godot (проверка, что модели грузятся) |
| `trees` | [породы] | пересобрать деревья + `kinds.json` + импорт |
| `houses` / `cars` / `places` | [имена через запятую] | рендер-превью моделей в Blender → `out/*.png` |
| `treeshow` | `варианты` [human/game] | рендер готовых деревьев |
| `scene` | `village,farm` или `@x:y` | расстановка построек → JSON + рендер сверху |
| `mapcheck` | [локации] | карта леса и построек → `out/map.png` |
| `treecheck` | [x,y] | деревья: треугольники, плотность |
| `shaders` | — | шейдеры на программном Vulkan, лог ошибок |

Снимок — около 40 с на точку, fps на снимках не настоящие (видеокарта программная). Реальные fps — только на телефоне владельца.

## Модели (Blender → Godot)
- Модели строятся скриптами: дома `tools/houses/house.py`, места `tools/houses/places.py`, машины `tools/cars/car.py`, старые постройки `tools/props/*.py`, всё вместе — `tools/props/build_all.py` → `godot/assets/props/props.glb`. Деревья — `tools/trees/treegen.py` (+ `broadleaf.py`) → `godot/assets/models/*_wood.glb|*_leaf.glb` + `kinds.json`.
- Готовые `.glb` большие (props.glb ~26 МБ) — через коннектор их не пушить. Пушить только скрипты: **сборка APK сама заметит, что скрипты изменились, пересоберёт модели в Blender и положит их в APK** (`tools/ci/models.sh`). Проверить заранее — `task=props` или `task=trees` (там же импорт в Godot) и превью `houses/cars/places`.
- Новые модели или текстуры требуют новый APK у владельца: подними `godot/apk_min.txt` до номера сборки, в которой они выйдут (номер = следующий run_number «Build Godot APK»). При пересборке моделей CI ставит это сам.
- Расстановка построек по карте — `godot/scripts/props.gd`, мир — `world_gen.gd`, `world.gd`.

## Обязательно в конце каждой правки
1. `task=parsecheck` — «PARSECHECK ok» (иначе сборка APK упадёт: она проверяет то же самое).
2. Запись в `CHANGES_DRAFT.md` (что и зачем).
3. Строка в `CLAUDE.md`, раздел «Текущее состояние»: «Сборка N: …, что проверить на телефоне».
4. Коммит в `main`, ссылка на APK владельцу.

## Нельзя
- Удалять или переписывать то, что владелец одобрил, без его слова.
- Пушить большие бинарные файлы (> 10 МБ).
- Менять ключ подписи и `export_presets.cfg` без нужды. (Для магазина ключ `android/android.keystore` и пароль нужно будет заменить секретными, а обновление кода по сети — выключить.)
